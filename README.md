# Brimholt

An original Godot tile-world prototype for up to **twelve LAN players**, including a
playing host. It uses native ENet, server-authoritative grid movement, collision,
smooth visual interpolation, a flat backpack with ground items, layered visible
equipment, a dense 384×384 world with safe towns, waystones, and ferries, and instanced dungeons. The map and all sprites are original;
the pixel art is generated by `tools/generators/make_sprites.py` and the world is painted in Godot's
TileMap editor. Brimholt is a working name;
trademark/name availability has not been verified.

Gear includes 15 [source-specific hunting weapons](docs/gameplay.md#hunting-weapons)
across levels 1–45, in addition to the regular tier sets and endgame relics.

## Setup and LAN play

Requires **Godot 4.5+**; development checks use **4.5.1**. Open `project.godot` in
Godot and press **F5**, or run from this folder:

```sh
godot --path .
```

Replace `godot` with your executable path if it is not on PATH. There is no Node
server, external service, API key, or bundled engine dependency.

After a fresh checkout (or new sprite sheets), import the assets once before running
from the command line: open the project in the Godot editor, or run `make import`
(`godot --headless --path . --editor --quit`). Otherwise sprites fail to load.

Without `--host` or `--join` (for example when you press F5 in the editor), the game opens
on a start menu over Cinder Crossing: click **Host a game** in one
instance. In another instance, enter the host's LAN IPv4 address and click **Join**. Use `127.0.0.1` only for two instances on the same
computer. All computers must use the same project files. Allow inbound **UDP
1234** through the host firewall; ENet does not use TCP/WebSockets.

```sh
# Playing host
godot --path . -- --host

# Client on the same computer; replace the IP for another LAN computer
godot --path . -- --join=127.0.0.1

# Optional dedicated host: no host character, up to twelve clients
godot --headless --path . -- --headless-server
```

For an alternative UDP port, add `--port=1235` after `--` on every instance.
This is a **trusted-LAN prototype**, not an Internet-ready service. Do not expose its port
to the public Internet.

### Saved characters

The host saves every character, so progress survives leaving and host restarts. Ground
items and monsters reset when the host stops.

- **Where:** only on the host, in Godot's user data folder under `saves/`
  (macOS `~/Library/Application Support/Godot/app_userdata/Brimholt/saves`, Windows
  `%APPDATA%\Godot\app_userdata\Brimholt\saves`, Linux `~/.local/share/godot/app_userdata/Brimholt/saves`).
  One file per character in `characters/`, the previous version as `.bak`, and the signing key
  `host.key`. Saves happen on joining, on leaving, every 30 seconds, and when the host quits.
  Use `--save-dir=PATH` for another folder or `--no-save` to play without saving.
- **Who you are:** each computer has a secret identity token in the same user data folder
  (`identity.cfg`). Joining sends it to the host, which keeps only its hash and loads the
  matching character. New characters start as Adventurers and choose a vocation in the game. Keep `identity.cfg`
  private; copy it to play your characters from another computer. To run two players on one
  computer, give one `--profile=NAME` (its own `identity-NAME.cfg`). One identity can be in a
  world only once.
- **Protection:** players never send or receive save data, so they cannot edit their
  characters. Each save is signed (HMAC-SHA256 with `host.key`): an edited, damaged, or swapped
  file is refused at join with a message, and the host can restore the `.bak`. Every loaded
  value is also checked against the current catalog. Whoever controls the host's account can
  still read `host.key` and forge saves, so for a game where nobody should be able to cheat, run
  a dedicated host (`--headless-server`) on a machine none of the players control.

## Controls

These are the default keys; every key can be changed (see below).

| Control | Action |
| --- | --- |
| WASD / arrows | Move one cardinal tile; hold to repeat |
| Left-click a creature | Lock it as your target (click again to release) |
| Space | Target the nearest monster |
| 1–9 | Cast the spell in action bar slot 1–9 (filled with your vocation's spells); hover a slot to see what it does |
| B | Open or close the spell book (every spell of your vocation; drag one onto the action bar) |
| C | Open or close the character window (stats explained, experience, party, skull, town rest) |
| Drag an item | Move it between backpack slots, equipment slots, and nearby tiles |
| Right-click item | Equip from the backpack, unequip into it, drink a potion, or (bank open) deposit it |
| Right-click tile / G | Pick up the top item on a tile (G: your tile, else the one you face) |
| Hover an item | Show its slot and stats |
| Right-click a person | Open their menu (ferrymen: **Travel**; vendors: **Trade**; bankers: **Bank**; quest givers: **Quests**) |
| Q / E | Drink a health / mana potion |
| Right-click / click a bar slot | Choose its spell / cast it |
| M | Open or close the world map |
| L | Show or hide the quest list (your tasks, their givers, and your progress) |
| Esc | Close menus, or release your target (cannot be rebound) |
| Leave / close window | Disconnect; leaving the host ends the session |

Walls, water, trees, townspeople, and players block movement. A gold ring marks your
character; the minimap in the side panel follows you.

More: [gameplay](docs/gameplay.md) (action bar, combat, parties, loot, death and skulls,
the world, inventory, vendors and bankers, town tasks and packs, gear tiers, the Hollow Reach,
final bosses and relics, stats).

## Development

Common tasks run through `make` (macOS and Linux; set `GODOT=/path/to/godot` if Godot is
not on PATH). `make` alone lists them.

```sh
make import        # after a fresh clone, new sprites, or moving files
make run           # start menu;  make host / make join ADDR=192.168.1.20 / make server
make test          # unit rules + real-ENet scenarios (about 1 minute)
make check         # import + test + offscreen visual checks
make playtest      # two-bot full-game playthrough with an HTML report (about 5 minutes)
make sprites       # regenerate assets/sprites (from game/data/items.json)
```

## Windows build

`make export-windows` builds `build/windows/Brimholt.exe` (the game data is embedded, about
100 MB), `Brimholt.console.exe` (the same game with a console, for dedicated servers and
logs), and `README.txt` with player instructions ([docs/windows.md](docs/windows.md)). It works
from macOS or Linux too. It needs the Godot 4.5.1 export templates: in the editor, Editor →
Manage Export Templates → Download and Install. The preset is in `export_presets.cfg`; it
includes `game/data/items.json` (read at runtime) and leaves out `tests/`, `tools/`, and
`docs/`. Zip the `build/windows` folder to share it. The executable is not code-signed, so
Windows SmartScreen asks players to confirm the first run, and Windows Firewall asks the host
to allow UDP 1234.

## Scope and reference licensing

Blessings, yellow and black skulls, loot protection, nested containers, player trading, procedural caves, floors, NPCs
other than the menu-driven ferrymen, waystones, vendors, bankers, and quest givers, world persistence (ground items and
monsters), and accounts beyond the per-computer identity token are outside this prototype.

[The Forgotten Server](https://github.com/otland/forgottenserver) (GPL-2.0) and
[OTClient Redemption](https://github.com/mehah/otclient) (MIT) are useful references
for high-level container/item concepts and inventory-event/UI separation, not
Godot/ENet dependencies. No third-party code is imported here. The only third-party assets
are CC0 (public domain) textures, listed with their licenses in
[`assets/third_party/CREDITS.md`](assets/third_party/CREDITS.md). Do not
copy or translate GPL code into this project without a licensing decision.
MIT reuse requires checking the specific files/dependencies and retaining their
copyright/license notices. Neither engine's source license grants rights to
proprietary Tibia sprites, maps, or client data.
